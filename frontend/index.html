How Fernet Works:

  • Unique salt ensures different keys from same password
  • AES-128 uses 10 rounds; Fernet authenticates ciphertext with HMAC
  • Military-grade encryption standard
  • All processing happens on secure server

Network Security Demonstration

Insecure Transmission (Obfuscation)

What an attacker sees:
POST /obfuscate HTTP/1.1
Host: example.com
Content-Type: application/json

{
"text": "This is a secret message",
"method": "caesar",
"shift": 3
}

Plaintext is fully visible to network attackers!

Man-in-the-Middle Attack Risk:
  • Attacker can read all data
  • Can modify data in transit
  • No authentication of sender
  • No protection against replay attacks
  • Easily intercepted on public WiFi

Secure Transmission (AES Encryption)

What an attacker sees:
POST /encrypt-text HTTP/1.1
Host: secure-server.com
Content-Type: application/json

{
"text": "gAAAAABmWf8Rq9pJ3V7K... (base64 encoded ciphertext)",
"password": "•••••••••••"
}

Without the encryption key, this is useless to attackers!

Security Features:
  • Illustrative ciphertext only; actual API uses HTTP
  • Even if intercepted, cannot be read
  • Integrity protection (tampering detectable)
  • Unique encryption each time (IV/salt)
  • Secure key derivation (PBKDF2)

Final Analysis & Recommendations

Never Use Client-Side Obfuscation For:
  • Passwords or credentials
  • Financial information
  • Personal data (PII)
  • Medical records
  • Any sensitive data
Always Use Proper Encryption For:
  • Data in transit (HTTPS + encryption)
  • Data at rest (encrypted storage)
  • Secure communications
  • Compliance requirements (GDPR, HIPAA)
  • Protecting user privacy
Best Practices Learned:
  1. Always encrypt sensitive data before transmission
  2. Use established cryptographic libraries (not custom code)
  3. Fernet for data, RSA for key exchange
  4. Use proper key derivation (PBKDF2, Argon2)
  5. Implement HTTPS (TLS) for all web communications
  6. Regularly update and patch cryptographic implementations

Learning Points

Why Encrypted Images Look Broken

  • Fernet completely randomizes pixel data
  • Image headers/metadata are also encrypted
  • Without the key, it's just random binary data
  • This is proof that encryption is working correctly

Real-World Usage

  • Medical Images: Protect patient X-rays and scans (HIPAA compliance)
  • Secure Cloud Storage: Encrypt photos before uploading to cloud
  • Surveillance Data: Protect CCTV footage from unauthorized access
  • Mobile Apps: Secure private photos in gallery apps

How Image Encryption Works

1. Image → Binary Data: Your image is read as raw bytes (1s and 0s)

2. Password + Random Salt: PBKDF2 generates 32-byte combined Fernet key

3. Fernet Encryption: Binary data encrypted using CBC mode

4. Output: Creates .enc file with salt + encrypted data

5. Decryption: Reverse process with correct password restores original perfectly
